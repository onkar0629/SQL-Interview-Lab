> [!NOTE]
>
> ## Question
>
> ### Business Context
>
> The Product Analytics team wants to identify the **best-selling product(s)** for every category.
>
> The dashboard should display only the product(s) with the **highest total sales amount** within each category.
>
> If multiple products have the same highest sales amount, **all of them must be returned**.
>
> As a Data Engineer, your task is to build this report.
>
> ### Problem Statement
>
> Find the **best-selling product(s)** in each category.
>
> Return the following columns:
>
> * `category`
> * `product_name`
> * `total_sales`
>
> ### Expected Output
>
> 1. Calculate the total sales for each product.
> 2. Return only the product(s) having the **highest total sales** within each category.
> 3. If multiple products tie for the highest sales, return all of them.
> 4. Sort the result by:
>
>    * `category`
    >    * `product_name`
>
> ### Constraints
>
> * Multiple sales can exist for the same product.
> * Products must first be aggregated before ranking.
> * Handle ties correctly.
> * Write production-quality SQL.
> * The production table contains hundreds of millions of sales records.

---

> [!TIP]
>
> ## Approach
>
> Before writing SQL, I broke the problem into four logical steps:
>
> * Aggregate sales for every product.
> * Calculate the total sales amount.
> * Rank products within each category.
> * Return only the highest-ranked product(s).

---

# My Solution

```sql
-- Step 1: Calculate total sales for every product
WITH product_sales AS
(
    SELECT

        category,

        product_name,

        -- Calculate total revenue generated by each product
        SUM(sale_amount) AS total_sales,

        -- Rank products based on total sales within each category
        DENSE_RANK() OVER
        (
            PARTITION BY category
            ORDER BY SUM(sale_amount) DESC
        ) AS rn

    FROM sales

    GROUP BY

        category,

        product_name
)

-- Step 2: Return only the best-selling product(s)
SELECT

    category,

    product_name,

    total_sales

FROM product_sales

WHERE rn = 1

-- Step 3: Sort the final result
ORDER BY

    category,

    product_name;
```

> [!TIP]
> **Interview Note**
>
> During the interview review, the initial solution used `COUNT(product_name)`, which counted the number of sales instead of calculating revenue. It was corrected to `SUM(sale_amount)` because the business requirement asked for the **best-selling product by total sales amount**.
>
> We also replaced `ROW_NUMBER()` with `DENSE_RANK()` to correctly return **all tied top-selling products**.

# Most Optimal Solution

```sql id="rq5t2k"
-- Step 1: Aggregate sales for each product
WITH product_sales AS
(
    SELECT

        category,

        product_name,

        -- Calculate total revenue generated by each product
        SUM(sale_amount) AS total_sales

    FROM sales

    GROUP BY

        category,

        product_name
),

-- Step 2: Rank products within each category
ranked_products AS
(
    SELECT

        category,

        product_name,

        total_sales,

        -- Assign rank based on total sales
        DENSE_RANK() OVER
        (
            PARTITION BY category
            ORDER BY total_sales DESC
        ) AS rn

    FROM product_sales
)

-- Step 3: Return only the highest-ranked products
SELECT

    category,

    product_name,

    total_sales

FROM ranked_products

WHERE rn = 1

ORDER BY

    category,

    product_name;
```

# Alternative Approach 2 — Aggregate + Join

```sql id="u0azjr"
-- Step 1: Calculate total sales for every product
WITH product_sales AS
(
    SELECT

        category,

        product_name,

        SUM(sale_amount) AS total_sales

    FROM sales

    GROUP BY

        category,

        product_name
),

-- Step 2: Find the highest sales in each category
max_sales AS
(
    SELECT

        category,

        MAX(total_sales) AS max_total_sales

    FROM product_sales

    GROUP BY category
)

-- Step 3: Return products matching the highest sales
SELECT

    ps.category,

    ps.product_name,

    ps.total_sales

FROM product_sales ps

JOIN max_sales ms
ON ps.category = ms.category
AND ps.total_sales = ms.max_total_sales

ORDER BY

    ps.category,

    ps.product_name;
```

> ## Why This Approach?
>
> ### My Solution
>
> **Strengths**
>
> * Compact and easy to understand.
> * Uses aggregation and window functions together.
> * Correctly handles ties using `DENSE_RANK()`.
>
> ---
>
> ### Most Optimal Solution
>
> **Strengths**
>
> * Separates aggregation and ranking into two logical steps.
> * Easier to debug and maintain.
> * Preferred for large production queries and ETL pipelines.
>
> ---
>
> ### Alternative Approaches
>
> **Subquery**
>
> * Useful when CTEs are unavailable.
> * Slightly less readable.
>
> **Aggregate + Join**
>
> * Works without window functions.
> * Helpful for databases that don't support analytical functions.

---

> [!IMPORTANT]
>
> ## Performance Considerations
>
> ### Recommended Index
>
> ```sql
> CREATE INDEX idx_sales_category_product
> ON sales(category, product_name);
> ```
>
> **Optional Covering Index**
>
> ```sql
> CREATE INDEX idx_sales_category_product_amount
> ON sales(category, product_name, sale_amount);
> ```
>
> **Why?**
>
> * Optimizes grouping by `category` and `product_name`.
> * Reduces sorting during aggregation.
> * A covering index may reduce table lookups when computing `SUM(sale_amount)`.
>
> **Time Complexity**
>
> Approximately **O(N log N)** because of aggregation and ranking.
>
> **Space Complexity**
>
> Depends on the grouped result set maintained by the execution engine.
>
> **Production Notes**
>
> * Aggregate before applying window functions.
> * Use `DENSE_RANK()` when ties must be preserved.
> * Review the execution plan (`EXPLAIN`) for very large datasets.

---

> [!WARNING]
>
> ## Common Interview Mistakes
>
> * Using `COUNT()` instead of `SUM()` for revenue calculations.
> * Ranking individual sales instead of aggregated product totals.
> * Using `ROW_NUMBER()` when ties should be returned.
> * Forgetting `DESC` while ranking.
> * Returning all products instead of only the top-ranked products.

> [!NOTE]

> ## Interview Takeaway
>
> This question combines **aggregation** with **window functions**, one of the most frequently tested analytical SQL patterns in Data Engineering interviews. Interviewers expect you to recognize that the data must first be aggregated (`SUM`) before applying a ranking function, and to choose the appropriate ranking function (`DENSE_RANK`) based on the business requirement to handle ties correctly.
